# The 208-case benchmark under COM 4p17p0, with COM Octave results

The 208-case corpus of [`../208_case_4p15p0/`](../208_case_4p15p0/README.md) (26 IEEE
802.3dj CR and KR channels x 4 package configurations x with and without crosstalk),
run on the COM **4p17p0** Reference Code release under GNU Octave and through SiCoPR
emulating the same release, case by case.

The results here are **COM Octave results**: the IEEE 802.3 COM Reference Code run under
GNU Octave. No MATLAB results exist for 4p17p0; none are published here in any case.

| file | what it is |
|---|---|
| `cases_com_octave.csv` | one row per case: case id, condition, package case, sweep row, workbook, THRU file, aggressor counts, the COM Octave results (COM_dB, FOM, itick, ERL, VEC_dB, VEO_mV, ICN_mV, DER_thresh, DER_MLSE, DER_DFE, CTLE_DC_gain_dB, TXLE_taps, DFE_taps), and SiCoPR's difference from each (`d_*_sicopr_minus_octave`) |

The channel list (IEEE download URLs and SHA-256) and the eight configuration workbooks
are the same corpus's: `../208_case_4p15p0/channels.csv` and `../208_case_4p15p0/configs/`.

## Agreement, SiCoPR against COM Octave

| | value |
|---|---|
| cases | 208, no errors |
| COM, max abs difference | 5.15e-14 dB (median 8.88e-15 dB) |
| FOM, max abs difference | 6.01e-12 dB |
| sampling phase (itick) identical | 208 / 208 |
| CTLE DC gain identical | 208 / 208 |
| Tx FFE taps identical | 208 / 208 |
| VEO, max abs difference | 7.36e-12 mV |
| VEC, max abs difference | 1.37e-13 dB |
| ERL, max abs difference | 0 dB |
| DER_MLSE, max abs difference | 5.43e-05 (the bin-edge reading every engine pair shows; COM is unaffected) |

COM spans -4.82 to 6.68 dB across the set, and 123 of the 208 cases fail
the 3 dB threshold.

## Against the 4p15p0 benchmark

The same 208 cases' COM Octave results in [`../208_case_4p15p0/`](../208_case_4p15p0/README.md),
release to release (both sides COM Octave; the 4p15p0 results came through an earlier
Octave route, see that README): COM within 5.03e-14 dB, FOM within 2.5e-12 dB,
sampling phase identical on 208 / 208 and Tx FFE within 1.11e-16. On this corpus the two
releases compute the same answer to arithmetic noise. Per-case detail is in the
si-studies release of the run.

## Running it

```powershell
python -m sicopr ../208_case_4p15p0/configs/<workbook>.xlsx <thru.s4p> --fext <f1.s4p ...> --next <n1.s4p ...>
```

(4p17p0 is the default; `--matlab-version 4p17p0` says so explicitly.) To compare at full
precision use `tools/_sicopr_case.py` or `tools/octave_compare.py`, not `results.csv`.
